# 현장 증거 원장

이 디렉터리는 심사 제출용 증거를 모아 둔다. **증거는 세 종류로 엄격히 구분해 표기한다.**

| 표기 | 뜻 | 발표 시 허용되는 말 |
|---|---|---|
| **실측** | 운영 배포본 또는 공사 OpenAPI에 실제 호출해 받은 응답·측정값. 원본 파일로 재대조 가능 | "실측했다", "관측됐다" |
| **AI 조사** | AI 가상 페르소나 기반 조사. 조건과 응답 수치는 실측이지만 프로필·감정·평점은 생성물 | "AI 가상 페르소나 조사에서 관측된 참고 수치" |
| **없음** | 아직 수집하지 않았다 | "아직 측정하지 않았다" (목표치를 실측치처럼 말하지 않는다 — 기획 15.7) |

파일 행을 채웠다는 사실만으로 증거가 검증되지는 않는다. 운영자 검토, 중복 제거, 개인정보 점검을 거친 원장만 출시 증거 API에 연결한다.

원장에는 인증키, 정확한 현재 좌표, 연락처, 건강정보, 내부 비공개 URL을 기록하지 않는다.

## 원본 응답 취급 규칙 (사고 후 수립)

이 조사 중 **공용 임시 디렉터리가 동시 실행 세션에 덮여 원본 4건이 손실되고, 1건은 다른 코호트 응답으로 대체됐다.** 이후 규칙:

1. 응답을 받으면 **즉시** `evidence/<코호트>/raw/`에 저장한다. 공용 스크래치패드에 두지 않는다.
2. 파일명에 **requestId 앞 8자리**를 포함한다. 본문 수치를 인용할 때 파일의 requestId를 재파싱해 일치를 확인한다.
3. 검증 불가한 파일은 **보관하지 않고 폐기**하고, 동일 조건으로 재호출해 수치가 재현된 회차만 남긴다(A 코호트가 이 절차를 밟았고, C 코호트는 밟지 않았다 — 두 코호트의 증거 강도가 다르다).
4. 쿠키 자루(`ck_*.txt`)와 응답 헤더 덤프는 보관하지 않는다.
5. 보관 후 디렉터리 전체를 키 문자열(`serviceKey`/`appKey`/`Authorization`/`KakaoAK`/`Bearer`/`apiKey`/`secret`/`set-cookie`)로 검사한다. **2026-08-05 검사 결과 노출 0건.**
6. 한글 본문은 UTF-8 파일로 저장해 `curl --data-binary @파일`로 보낸다. Windows Git Bash의 inline `curl -d`는 한글을 CP949로 재인코딩해 응답 문구에 깨진 라벨을 남긴다(제품 결함 아님).

통과해야 한다.
