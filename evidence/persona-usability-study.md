읽는 방법 세 가지를 함께 적는다.

1. **이 17.4%는 기획 14.2의 `사용자 과업 성공률` KPI(목표 85%)가 아니다.** KPI는 15~20명 실사용자 테스트를 요구하고, 이 수치는 AI 페르소나 판정이다.

## 9. 이 문서가 주장하지 않는 것

- 실제 사용자를 테스트했다고 주장하지 않는다. 페르소나 23명은 전부 AI 생성이다.
- 17.4%와 2.74를 KPI 실측치로 주장하지 않는다.
- 코호트 6개·23명으로 전체 사용자를 일반화하지 않는다. 조건이 어려운 사용자에게서 **어느 축이 먼저 무너지는지**를 보인 것이다.
- B·F 코호트 15건과 C 코호트 6건의 수치는 **원본 응답으로 대조할 수 없다**(6절). 이 수치들은 requestId와 본문 기록에만 근거한다.
- C-P02의 수치는 `p02.json`이 다른 코호트 응답으로 덮여 있어 **재파싱 대조가 불가능하다**.
- 마찰 목록의 심각도 순서는 조사자 판단이다. 실사용자 우선순위와 다를 수 있다.
- 코드 인용 행 번호(`engine.ts:2121-2130` 등)는 조사 시점 저장소 상태 기준이며, 이 조사에서 소스 파일을 수정하지 않았다.

## 10. 재현 방법

```bash
# 지역·시군구 코드
GET  /api/v1/regions
GET  /api/v1/regions/{areaCode}/districts

# 빈 시간 추천 (일정 등록 불필요) — 요청 본문은 raw/의 req_*.json 그대로 사용
POST /api/v1/recover

# 등록 일정 복구 — 노드 2개(하나는 locked+reservation) 먼저 등록
POST /api/v1/itineraries    → itineraryId
POST /api/v1/recover        (itinerary.id 지정, occurredAt은 서버 시각 ±5분)

# 인사이트 (F 코호트)
GET  /api/v1/insights/missions[?areaCode=&sigunguCode=&limit=]
GET  /api/v1/insights/regions/{areaCode}?sigunguCode={code}
```

주의 사항 4건.

1. `POST /api/v1/recover`는 **분당 15회 한도**(클라이언트 식별자 단위). 세션 쿠키를 재사용할 것.
2. **한글 본문은 UTF-8 파일로 저장해 `curl --data-binary @파일`로 보낼 것.** Windows Git Bash에서 inline `curl -d`로 보내면 CP949로 재인코딩돼 `origin.label`이 응답 `scope.originLabel`과 why 문구에 깨진 채 노출된다(C 코호트 1·2차에서 실제 발생, `p01c.json`에서 정상 복구 확인). **제품 결함이 아니라 조사 도구 문제다.**
3. Cloudflare가 python urllib UA를 403으로 막는다. curl을 쓸 것.
4. **원본 응답은 공용 임시 디렉터리에 두지 말 것.** 이 조사에서 다른 세션이 파일을 덮어 A 코호트 4건이 폐기됐고 C 코호트 1건은 다른 코호트 응답으로 대체됐다(6절). `evidence/<코호트>/raw/`에 requestId를 파일명에 포함해 즉시 저장할 것.
